# Development Log

Keep entries public-ready: completed work, decisions and rationale, useful failed approaches, validation, and durable lessons.

## 2026-08-11 (departments)

- Added departments as the unit of scoping. Design settled by asking rather than guessing, because the readings diverged sharply: the portal had no viewer identity at all, so "assign users to departments" could have meant scoping only the admin side. It means viewers, with a switch to turn anonymous browsing off entirely.
- Portal viewers reuse the existing authentication system with a new `is_admin` flag rather than a second user store. A parallel auth path would have been a liability, and this way local, AD, and Entra sign-in all work with the session handling already hardened.
- The schema and migration were built and verified first, against a copy of the live production database rather than a synthetic one: 2 locations, 3 links, 1 administrator, all preserved, the administrator still an administrator, and idempotent across three runs.
- **A regression the existing suite could not see.** With no departments defined a fresh install assigned `NULL` and the portal served an empty catalog. Nothing in 93 tests asserted that the portal returns links at all. A default public department is now guaranteed and unassigned records land in it.
- **"Public" initially meant "anonymous only", which was wrong.** A viewer assigned to IT saw only IT, so signing in could lose them access to the company-wide department they could see while signed out. Public now means visible to everyone; a viewer sees their assignments plus the public departments. Since a link belongs to strictly one department, a public department is the only way to publish something to everyone, which makes this the difference between the model working and not.
- **Viewer accounts silently broke the lockout guard.** It counted `enabled = 1` rows, so with one administrator and one viewer, deleting the administrator passed the check and left nobody able to administer anything. Demoting or disabling the last administrator was the same lockout by another route. All three are now refused, and the guard counts administrators. Verified by restoring the old guard and watching the new test fail with `200 != 400` before restoring the fix — a test that has not been seen to fail has not been shown to test anything.
- A location's links follow the location, so the department field is derived rather than editable on a location link. Otherwise a link could be visible to a department that cannot see the location it sits under.
- The portal stylesheet defined none of `.hidden`, `.primary-button`, `.secondary-button` or the `.sso-*` rules the new markup used; `index.html` only loads `styles.css`. Without adding them the sign-in gate would have rendered permanently visible and unstyled.
- Admin UI verified by driving it in a browser rather than by inspection, which is how the stale checkbox list was found: creating a department refreshed the two `<select>` pickers but not the per-user access checkboxes, so a newly created department could not be assigned until a reload.
- Deliberately deferred: mapping directory groups to departments. Jordan asked for manual assignment first, and directory sign-in still grants administrator exactly as before, so nothing regressed. The `directory_departments` and `directory_memberships` tables are in place so that stage needs no migration.
- Validation: 98 tests, 23 new. The department model was also exercised end to end against a live server before any interface existed, which is what made the UI work go quickly.

## 2026-08-11 (data directory error message)

- Fixed the diagnostic that cost the most time during the first deployment of `2026.08.11.002`. An unwritable data directory produced `sqlite3.OperationalError: attempt to write a readonly database` from `PRAGMA journal_mode = WAL`, naming neither the directory nor the user, and pointing at a database problem that did not exist. `ensure_database` now preflights the directory with a write probe and reports the path, the effective uid and gid, and the fix — including the specific cause that produced it: dropping all capabilities strips root's `CAP_DAC_OVERRIDE`, so a container running as root is still bound by the directory mode.
- The remaining `PRAGMA` failure path is wrapped too, so anything the preflight cannot anticipate is still reported against the database path rather than as a bare pragma error.
- The two permission tests skip on Windows, where the POSIX mode has no equivalent, and skip under root, which bypasses permission checks entirely. They were verified on Linux specifically because that is the only place they execute — a green Windows run proves nothing about them. A third test asserts the write probe leaves no file behind.

## 2026-08-11 (auth page rework)

- Reworked the Authentication tab so the two directory providers stop rendering their full forms inline. Chose compact status rows plus a per-provider dialog over the toggle that was also suggested: a show-one-at-a-time toggle hides whether the *other* provider is enabled, which is exactly the fact an administrator opens that page to check. Rows keep both states visible and still collapse the tab from roughly 2,200px to 468px.
- Used a native `<dialog>` with `showModal()`, so Escape handling and focus trapping come from the browser rather than from script.
- A `<form method="dialog">` close button nested inside another form is invalid HTML: it silently truncates the outer form and orphans every field after it. The close controls are therefore plain `type="button"` elements, the dialogs live at top level outside `.auth-grid`, and a parser asserts `NESTED FORMS: 0` rather than trusting review.
- Reused the fingerprint method too. The provider forms were *moved* verbatim, never retyped, and a script compared the ordered list of every form control before and after: identical, 7 AD controls and 9 Entra controls preserved. That check is what makes a markup reshuffle of a working form safe to do quickly.
- **The local verification run destroyed its own database, and the cause was a defect in the new test suite.** `test_data_directory_is_never_served` wrote `data/links.db` and `data/.session_secret` inside the application directory to prove they are not served, then deleted them in tearDown. That directory is the default `DATA_DIR`, so running the suite while a local server was up overwrote and then removed the developer's live database. Fixed by using dedicated canary filenames and by making the fixture helper refuse to touch any path that already exists — failing loudly beats destroying data. Verified by hashing a live local database, running the full suite, and confirming the hash is unchanged and the server still serves.
- Follow-up on the same tab: the directory column had large gaps around its help text. `.tool-section` is a grid, and beside a taller neighbour its rows stretched to fill the column — the heading's row became 90px for 24px of text, the help text's 81px for 17px. Packing rows to the top with `align-content: start` took the content block from 431px to 207px.
- **Nearly dismissed that fix as a no-op by measuring the wrong thing.** Comparing element *edges* (`help.top - h4.bottom`) reported 8px before and after, because the inflated space is *inside* each stretched box, not between boxes. Only `getComputedStyle(section).gridTemplateRows` showed it: `90px 81px 215px` before, `21px 12px 146px` after. For a suspected stretch problem, measure track sizes, not gaps. Two earlier attempts also failed to reproduce it at all because the viewport was under the 900px breakpoint where `.auth-grid` collapses to one column and nothing stretches — reproduce the reported layout before concluding anything about it.
- Escape-to-close could not be verified in the automated browser: real typing reaches the page, but a synthesised Escape produces no `cancel` event on the dialog, so the harness is swallowing that key. Close button, backdrop click, save-then-close, and row refresh after save were all verified directly. Both themes and 375px mobile check out — dialog 337x715 inside a 375x812 viewport with an internally scrolling body and no horizontal overflow.

## 2026-08-11 (image publishing)

- Added `.github/workflows/publish.yml` so releases are built and pushed from CI rather than a workstation. This machine has no Docker, podman, or nerdctl and no stored registry credentials, and publishing to the Docker Hub namespace requires the account's own token, so a local build was not an option regardless of tooling.
- CI publishing is the better arrangement anyway: the image provenance is tied to a tagged commit, the unit tests gate the push, and the release stops depending on whichever machine happens to have Docker installed.
- The workflow runs the test suite before logging in, so a failing suite cannot produce a published image. It also refuses to publish when a pushed tag does not match the `VERSION` file, which is the mistake most likely to happen by hand.
- `provenance: false` keeps each tag to a single manifest entry. The `1.0.x` and `2026.07.09.001` tags carry an extra `unknown/unknown` attestation row from an earlier build method; the recent ones do not, and this matches the recent ones.
- Held to `linux/amd64` to match every release since `2026.08.09.001`. `2026.07.09.001` and `1.0.2` were also built for `linux/arm64`; adding it back is one line in `platforms:` if ARM hosts need it, and the image is pure Python so the cross build is cheap.
- Requires `DOCKERHUB_USERNAME` and `DOCKERHUB_TOKEN` repository secrets. These have to be added by the account owner; an agent should not be handling a registry token.

## 2026-08-11 (Entra ID)

- Added Microsoft Entra ID as a third authentication source, on the OIDC authorization code flow with PKCE. Rejected the resource owner password credentials grant even though it would have dropped straight into the existing username/password form: it does not support MFA or Conditional Access and is blocked in many tenants, which would have made the feature useless in exactly the environments that ask for it.
- No new dependencies. The ID token's signature is deliberately not verified, which is sound here rather than a shortcut: the token is read off a TLS connection this process opens to `login.microsoftonline.com`, and OIDC Core 3.1.3.7 allows TLS server authentication to substitute for signature checking on the code flow. Tenant, issuer, audience, nonce, and validity window are all still checked. JWKS verification would be mandatory only if a token were ever accepted from the browser, which never happens.
- The tenant ID is required to be a GUID rather than a domain name. With a domain-form authority the `tid` claim cannot be compared against configuration, and requiring the GUID makes `iss == authority/{tid}/v2.0` and `tid == configured` both exact. The portal labels it "Directory (tenant) ID", so this costs the administrator nothing.
- Flow state (state, nonce, PKCE verifier) lives in a short-lived signed cookie scoped to `/api/auth/entra` rather than server-side storage, so nothing needs eviction and pending sign-ins survive a restart. A test asserts the verifier never appears in the redirect to Microsoft and that the challenge is its S256 hash.
- Group authorization uses group object IDs from the `groups` claim, with app roles as an alternative. Deliberately no Microsoft Graph calls: `/me/memberOf` needs `GroupMember.Read.All`, which is a much larger consent ask than this feature warrants. The group overage case past ~200 groups is detected and logged with a pointer to app roles instead of silently denying.
- Directory config changes now revoke that directory's sessions. First attempt stamped the epoch at `now + 1` reusing the per-account revocation helper, which broke two tests and would have broken production: an administrator enabling Entra invalidated the session created moments later, because the new session's issue time fell inside the same second. Config epochs now stamp `now`, which keeps a same-second sign-in valid and only drops sessions from earlier seconds. The remaining sub-second race requires authenticating in the same second as the save and is not meaningfully exploitable.
- Confirmed the epoch check sits only on the directory branch of session validation, so a local administrator configuring Entra is never signed out. That has its own test, because it is the kind of thing that would be discovered the hard way.
- The two epoch tests were rewritten to pin their timestamps to the stored epoch rather than wall-clock offsets. Written against the clock they passed locally and would have gone flaky in CI.
- UI verified in a real browser rather than by inspection: button visible and correctly sized, hidden once signed in, error banner rendering from the fixed message table with the reason code stripped from the URL afterwards, all three authentication sections present, the client secret field empty with a "stored" note, no console errors, and no horizontal overflow at 375px in dark mode.
- Validation: 71 tests passing across four runs (26 new, covering config validation, the redirect and callback, state and nonce mismatch, claim rules one per case, authorization by user, group, and role, group overage, and session revocation). The live Microsoft round trip is the one thing not covered — it needs a real tenant and app registration.

## 2026-08-11 (security review)

- Security review of `aa45b97` found two critical unauthenticated defects, both reproduced against a running server before any code changed. `DATA_DIR` defaults inside the static root, so `GET /data/.session_secret` returned the signing secret; because sessions were signed from the expiry timestamp alone and carried no identity, that secret was enough to mint a working admin cookie and write through `/api/locations`. Separately, the `translate_path` override had replaced the base handler's sanitizer without reimplementing it, so `curl --path-as-is /../file` read outside the application directory.
- Root cause for both: overriding `translate_path` on `SimpleHTTPRequestHandler` while keeping writable state under the served root. Serving is now an explicit allowlist plus a resolved-path containment check plus a data-directory exclusion — three independent controls, so the exposure does not return if `DATA_DIR` moves back inside the app directory.
- Chose an allowlist over relocating `DATA_DIR` to `/data`. Relocating is cleaner in isolation but would have silently started an empty database for anyone who updated the image without updating their Compose file. The allowlist closes the hole with no upgrade risk; the README now recommends an external `DATA_DIR` as a second layer.
- Sessions were rebuilt to name their account and authentication source, validated against a per-account revocation epoch in a new `session_epochs` table. Logout, password change, rename, disable, and delete now all revoke. Per-account epochs were chosen over a single global one so revoking one administrator does not sign out every AD user.
- Enforcing the location foreign key required a table rebuild, not just `PRAGMA foreign_keys = ON`: without `ON UPDATE CASCADE` the existing rename path would have violated the constraint. Migration was verified against a database generated by the released code, seeded with an orphaned link and a general link carrying a stale location code. All three links survived, the orphan's dangling code was cleared and logged rather than deleted, the legacy administrator still authenticated, and renaming a location then cascaded correctly.
- Rejected a strict http/https-only URL allowlist in favour of denying the script-bearing schemes. An allowlist could not distinguish a bare `intranet:8080/app` from an unknown scheme, and this is an intranet link portal where `smb:` and `rdp:` targets are legitimate. CSP `script-src 'self'` already blocks `javascript:` navigation, so the check is a second layer rather than the only one.
- A flaky connection abort in the new suite turned out to be a server defect, not a test artifact: answering a `POST` with `401` without consuming the request body leaves unread bytes in the socket, so the close sends an RST and can destroy the response. Under an expired session the browser would have seen a connection reset instead of the `401` JSON. Bodies are now drained before early error responses.
- Added `tests/test_http.py`, 40 request-level tests. The existing suite covered only first-run bootstrapping, which is precisely why none of the critical or high findings were caught — all of them are invisible from inside the module. Test runtime is held to about 7 seconds by lowering the KDF iteration count (it is stored per-hash, so this only affects hashes the tests create) and shortening the server poll interval.
- Validation: 45 tests passing across four consecutive runs, byte compilation clean, every original exploit re-run against the patched server and confirmed closed, the login timing oracle measured down from 3.53x to 1.21x, lockout observed engaging on the sixth attempt, and the application's own routes confirmed still serving. Docker build left to CI; the Dockerfile is unchanged.
